# kitty vpn

текущая версия: **1.0.7**

telegram-бот для управления vpn-подписками через 3x-ui.

## функции пользователя

- `/start` — определяет, есть ли пользователь в локальной базе. для нового пользователя показывает trial. для существующего показывает его подписку.
- `🎁 начать trial` — создаёт клиента в 3x-ui на `TRIAL_HOURS` часов (сейчас 12), лимит 1 hwid, сохраняет его в sqlite и выдаёт json-подписку.
- `🔗 подключиться` — показывает статус подписки, оставшееся время, количество устройств и json-url.
- `📱 устройства` — показывает зарегистрированные hwid и позволяет удалить все устройства.
- `💳 купить / продлить` — показывает тариф 3 устройства / 80 ₽ в месяц и контакт администратора. автоматической оплаты нет.
- `🆘 поддержка` — открывает тикет через `@kittyvpn_support_robot`.
- `ℹ️ о сервисе` — ссылки на политику конфиденциальности и пользовательское соглашение.

при каждом `/start` администратор получает username, telegram id и известный sub id.

## админ-панель

открывается только командой `/kittyadmin` и только для `ADMIN_ID`.

### привязать подписку

`🔗 привязать подписку`

формат:

`telegram_id sub_id`

бот ищет sub id среди клиентов 3x-ui и связывает подписку с telegram id.

### создать оплаченного пользователя

`💳 создать оплаченного юзера`

администратор отправляет telegram id.

создаётся клиент:

- срок: 30 дней;
- лимит hwid: 3;
- `totalGB = 0`;
- email: `tg_<telegram_id>`;
- группа: `paid`.

после создания подписка сохраняется в sqlite и json-url отправляется администратору.

### действия с пользователем

`👤 действия с пользователем`

- продление на 30 дней по `sub_id` через 3x-ui `bulkAdjust`;
- бан по `sub_id` через 3x-ui `bulkDisable`.

после продления локальная база обновляется, если у клиента есть `tgId`.

## подписки

используется только json-формат:

`https://87.121.82.175:2096/jsnn/<sub_id>`

## 3x-ui

используемые inbound:

- `8` — 🇫🇮 финляндия
- `20` — 🇸🇪 швеция
- `30` — 🇩🇪 германия
- `31` — 🇵🇱 польша

при создании клиента все четыре inbound подключаются одновременно.

основные операции api:

- список inbounds;
- получение клиента;
- создание клиента;
- поиск по email и sub id;
- продление;
- отключение;
- получение hwid;
- удаление всех hwid;
- получение traffic.

## структура проекта

### `bot.py`

telegram-логика и бизнес-логика: команды, меню, trial, подписки, hwid, поддержка, информация о сервисе и админские действия.

### `xui.py`

обёртка над 3x-ui api: http/curl-запросы, клиенты, inbounds, subscription url, hwid, продление, бан, создание paid-клиента.

### `db.py`

sqlite через `aiosqlite`.

таблица `users`:

`tg_id`, `username`, `email`, `sub_id`, `subscription_url`, `status`, `created_at`, `expires_at`.

### `config.py`

загрузка env-переменных и настроек.

## конфигурация

обязательные переменные:

- `BOT_TOKEN`
- `ADMIN_ID`
- `XUI_API_TOKEN`

дефолты:

- `XUI_HOST=https://127.0.0.1:1337/ZoxJbyRPdLe5t4y243`
- `TRIAL_HOURS=12`
- `TRIAL_LIMIT=4`
- `DATABASE_PATH=/opt/vpn-bot/bot.db`

секреты не коммитить в git.

## окружение

- python 3.12+
- aiogram 3.x
- aiohttp
- aiosqlite
- python-dotenv
- apscheduler

systemd-сервис: `vpn-bot`

рабочая директория: `/opt/vpn-bot`

после изменения кода:

`systemctl restart vpn-bot`

перезапуск systemd не синхронизирует файлы с github — серверную копию нужно отдельно обновлять через git.

## важные детали для ai-агентов

перед изменениями читать как минимум `bot.py`, `xui.py`, `db.py`, `config.py`.

сохранять существующие callback_data и совместимость с текущей sqlite-схемой.

не добавлять секреты в репозиторий.

при изменении функционала обновлять README.

при каждом релизе менять `BOT_VERSION` в `bot.py`.

не менять рабочие 3x-ui порты без необходимости.

github и сервер — отдельные копии проекта.

## ограничения

- автоматической оплаты нет;
- автоматического продления нет;
- `TRIAL_LIMIT` сейчас не используется отдельной проверкой в `bot.py`;
- автоматической очистки sqlite нет;
- срок действия контролируется через `expiryTime` 3x-ui.
