## что умеет бот

kitty vpn — полноценная telegram-панель для небольшого vpn-сервиса.

### основные возможности

- автоматическая выдача trial;
- проверка подписки на telegram-канал перед выдачей trial;
- управление подпиской через 3x-ui;
- json-subscription для vpn-клиентов;
- отображение оставшегося срока;
- отображение количества занятых устройств;
- просмотр HWID-устройств;
- удаление всех зарегистрированных устройств;
- покупка подписки на 1 или 3 месяца;
- выбор от 3 до 10 устройств;
- автоматическая оплата через RollyPay;
- проверка webhook-подписей;
- защита от повторной обработки платежа;
- промокоды с ограничением количества использований;
- реферальная система;
- автоматические уведомления об окончании подписки;
- уведомления о новых устройствах;
- обработка пользователей, заблокировавших бота;
- массовые рассылки по группам;
- очередь рассылок с ограничением скорости;
- личные сообщения пользователям;
- режим технических работ;
- отдельная админ-панель;
- уведомления администратора о важных событиях;
- автоматическая миграция sqlite-базы при запуске.

# пользовательская часть

## старт и trial

при `/start` бот определяет состояние пользователя.

если пользователь уже существует и имеет профиль — открывается главное меню.

для нового пользователя доступен выбор:

- подписаться на канал и получить trial;
- сразу перейти к покупке подписки.

### проверка канала

перед выдачей trial бот проверяет, состоит ли пользователь в:

`@kittyvpnoff`

если подписки на канал нет, trial не выдаётся.

### trial

текущий trial создаётся на **24 часа**.

при создании:

1. создаётся клиент в 3x-ui;
2. назначается группа `trial`;
3. создаётся subscription id;
4. создаётся json-ссылка;
5. пользователь сохраняется в sqlite;
6. администратор получает уведомление.

пример уведомления админу:

```text
🎁 подключён trial

👤 username: @username
🆔 telegram id: 123456
🔗 sub id: ...
```

trial нельзя повторно получить для уже существующего активного профиля.

главное меню kitty vpn

## подписка

раздел **🔗 подписка** показывает актуальное состояние VPN-подписки.

бот сначала пытается найти клиента в 3x-ui по telegram id.

если клиент не найден — используется старый email из sqlite, что обеспечивает совместимость со старыми аккаунтами.

показывается:

- количество занятых устройств;
- установленный лимит устройств;
- оставшееся время;
- subscription URL;
- инструкция по добавлению подписки в Happ.

### subscription URL

используется json-подписка:

```text
https://87.121.82.175:2096/jsnn/<sub_id>
```

в интерфейсе есть кнопка **📋 скопировать ссылку**.

## устройства

раздел **📱 устройства** получает HWID-устройства непосредственно из 3x-ui.

пользователь видит:

- количество использованных устройств;
- максимальный лимит;
- модель/название зарегистрированных устройств.

доступно действие:

**🗑 удалить все устройства**

после удаления пользователь может подключить устройства заново.

## покупка и продление

покупка доступна через **💳 купить / продлить**.

### количество устройств

можно выбрать от **3 до 10 устройств**.

базовая цена:

- 3 устройства — **80 ₽ / месяц**;
- каждое дополнительное устройство — **+50 ₽ / месяц**.

то есть месячная цена рассчитывается по формуле:

```text
80 + (количество_устройств - 3) × 50
```

### срок

доступны:

- 1 месяц;
- 3 месяца.

для 3 месяцев используется скидочная формула:

```text
месячная_цена × 3 × 70 / 80
```

после подтверждения бот:

1. создаёт платёж в RollyPay;
2. сохраняет платёж в sqlite;
3. показывает пользователю сумму;
4. отправляет кнопку оплаты;
5. ждёт подтверждённый webhook;
6. после успешной оплаты автоматически продлевает клиента в 3x-ui;
7. устанавливает выбранный лимит устройств;
8. переводит клиента в группу `paid`;
9. отправляет пользователю подтверждение.

## промокоды

пользователь может открыть:

**🎟 промокод**

и отправить код одним сообщением.

### проверки

при активации проверяется:

- существует ли промокод;
- включён ли он;
- не истёк ли срок действия;
- не закончился ли лимит использований;
- не использовал ли этот пользователь код раньше;
- существует ли у пользователя подписка.

после успешной активации к подписке добавляется указанное количество дней.

использование промокода записывается отдельно, поэтому один пользователь не может использовать один и тот же код повторно.

### уведомление админу

после успешной активации администратор получает:

```text
🎟 активирован промокод

🎟 промокод: KITTY7
🎁 добавлено: +7 дней
👤 кому: @username
🆔 telegram id: 123456
📦 остаток использований: 9
```

если лимит не установлен, вместо количества показывается:

```text
без ограничений
```

## реферальная система

у каждого пользователя есть персональная реферальная ссылка:

```text
https://t.me/<bot>?start=ref_<telegram_id>
```

при первом переходе нового пользователя по ссылке создаётся связь между пригласившим и приглашённым.

### статистика

пользователь видит:

- 👤 сколько друзей приглашено;
- 🎁 сколько дней заработано.

### награды

за переход друга по реферальной ссылке и первый `/start`:

**+1 день**

за каждый месяц, оплаченный приглашённым:

**+5 дней**

например, при оплате на 3 месяца реферер получает **+15 дней**.

дни начисляются сразу к подписке реферера, даже если она уже закончилась.

если у реферера ещё нет клиента в 3x-ui, награда сохраняется как pending и автоматически применяется сразу при первом создании подписки.

---

## уведомления

бот работает с отдельным фоновым notification worker.

проверка выполняется примерно раз в минуту.

### trial

если до окончания trial осталось не больше 3 часов, пользователь получает напоминание.

уведомление отправляется только один раз для конкретного срока.

### платная подписка

для платной подписки предусмотрены два напоминания:

- когда осталось не больше 24 часов;
- когда осталось не больше 1 часа.

после окончания срока отправляется уведомление:

**❌ срок подписки закончился.**

уведомления дедуплицируются через sqlite, поэтому перезапуск бота не должен приводить к повторной отправке одного и того же напоминания.

---

## мониторинг новых устройств

фоновый воркер периодически получает HWID-устройства пользователя из 3x-ui.

бот хранит снимки уже известных устройств.

если появляется новое устройство, пользователь получает уведомление с:

- названием устройства;
- временем первого подключения;
- кнопкой перехода к списку устройств.

первая синхронизация существующих устройств не считается новым подключением, поэтому старые устройства не вызывают массовый спам уведомлениями.

## рассылка

администратор может сделать массовую рассылку определённой группе или всем пользователям.

### группы

доступны:

- 👥 все;
- 🟢 активные;
- 🧪 trial;
- 💳 paid;
- ⌛ истёкшие.

### процесс

1. выбирается группа;
2. администратор отправляет одно сообщение;
3. бот показывает предпросмотр;
4. показывает количество получателей;
5. администратор подтверждает отправку;
6. задача помещается в очередь;
7. отдельный worker отправляет сообщения постепенно;
8. после завершения администратор получает статистику.

поддерживаются обычные telegram-сообщения, включая:

- текст;
- фото;
- видео;
- документы;
- другие сообщения, которые Telegram разрешает копировать.

бот использует `copy_message`, поэтому форматирование и содержимое исходного сообщения сохраняются настолько, насколько это поддерживается Telegram.

### ограничение скорости

между отправками используется небольшая задержка:

```text
BROADCAST_DELAY = 0.06
```

если Telegram возвращает `RetryAfter`, worker автоматически ждёт указанное время и продолжает рассылку.

### результат

администратор получает:

```text
✅ рассылка завершена

👥 группа: всем
📨 всего: 100
✅ отправлено: 96
🚫 заблокировали бота: 3
❌ ошибок: 1
```

**🗑 очистить тестовый аккаунт**

## уведомления о блокировке бота

если бот пытается отправить пользователю уведомление, а Telegram возвращает `Forbidden`, пользователь считается заблокировавшим бота.

администратор получает:

```text
🚫 пользователь заблокировал бота

👤 username: @username
🆔 telegram id: 123456
```

есть кнопка:

**🔓 разблокировать уведомления**

после разблокировки бот снова сможет пытаться отправлять пользователю уведомления.

запись о блокировке хранится в sqlite, поэтому повторные ошибки доставки не должны создавать бесконечный поток одинаковых уведомлений админу.

заблокированные пользователи также автоматически исключаются из массовых рассылок.

# оплата через rollypay

для платежей используется:

**RollyPay**

бот работает с API через `rollypay.py`.

### создание платежа

при создании платежа передаются:

- сумма;
- RUB;
- уникальный order id;
- описание;
- telegram id;
- количество дней;
- количество устройств;
- количество месяцев;
- test-режим.

платёж сохраняется в таблице `payments`.

### webhook

webhook работает отдельным aiohttp-сервисом.

endpoint:

```text
POST /rollypay/webhook
```

текущий callback:

```text
https://87.121.82.175:8443/rollypay/webhook
```

используется HTTPS.

### безопасность webhook

бот проверяет:

- наличие подписи;
- HMAC-SHA256 подпись;
- timestamp;
- payment id;
- существование платежа;
- test-режим;
- сумму;
- валюту.

если платёж уже имеет статус `paid`, повторная выдача подписки не производится.

### успешная оплата

после подтверждённой оплаты:

1. находится пользователь;
2. находится его subscription id;
3. 3x-ui продлевает клиента;
4. устанавливается выбранный лимит HWID;
5. клиент переводится в группу `paid`;
6. обновляется срок в sqlite;
7. платёж получает статус `paid`;
8. обрабатывается реферальная награда;
9. применяются накопленные pending-награды;
10. пользователь получает уведомление;
11. администратор получает информацию о платеже.

пример уведомления админу:

```text
✅ подписка продлена автоматически

👤 telegram id: 123456
💳 payment id: ...
🎁 добавлено: 30 дней
📱 устройств: 3
⏳ expires: ...
👥 реферал: нет
```

### неуспешные платежи

для отменённых или истёкших платежей пользователь получает уведомление.

администратор также получает информацию о webhook-событиях и проблемах проверки.

# база данных

используется **SQLite** через `aiosqlite`.

по умолчанию:

```text
/opt/vpn-bot/bot.db
```

### users

основная информация о пользователях:

- telegram id;
- username;
- email;
- sub id;
- subscription URL;
- статус;
- дата создания;
- срок действия.

### promo_codes

хранит промокоды:

- `code`;
- `reward_days`;
- `max_uses`;
- `used_count`;
- `expires_at`;
- `enabled`.

### promo_uses

хранит факт использования промокода конкретным пользователем.

первичный ключ:

```text
(code, tg_id)
```

это предотвращает повторное использование одного кода одним пользователем.

### payments

хранит:

- payment id;
- order id;
- telegram id;
- сумму;
- валюту;
- количество дней;
- test-флаг;
- статус;
- дату создания;
- дату обновления;
- лимит устройств;
- количество месяцев.

### referrals

хранит связь:

```text
referrer → referred user
```

### referral_rewards

хранит:

- платёж;
- приглашённого пользователя;
- реферера;
- количество наградных дней;
- применена ли награда;
- дату создания.

### bot_settings

хранит настройки бота, например:

- режим технических работ;
- сообщение технических работ.

### notification_blocked_users

хранит пользователей, которым бот не может отправлять сообщения.

### notification_log

используется для дедупликации автоматических уведомлений.

### device_snapshots

хранит уже замеченные HWID-устройства.

# уведомительный воркер

бот запускает отдельный asyncio worker:

```text
notifications_worker(bot)
```

он работает примерно раз в минуту.

воркер одновременно отвечает за:

- напоминания о trial;
- напоминания об окончании платной подписки;
- уведомления об окончании;
- мониторинг новых устройств.

ошибки отдельного пользователя не должны останавливать весь worker: исключения логируются и обработка продолжается.

# установка и запуск

требования:

- linux;
- python 3.12+;
- 3x-ui;
- telegram bot token;
- sqlite;
- RollyPay для автоматической оплаты.

установка зависимостей:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

проверка синтаксиса:

```bash
.venv/bin/python -m py_compile bot.py db.py config.py xui.py rollypay.py webhook.py
```

запуск приложения:

```bash
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8443
```

приложение одновременно поднимает telegram webhook, rollypay webhook, apscheduler и очередь taskiq.

```text
rollypay-webhook.service
```

при старте `bot.py` автоматически вызывает `init_db()`, поэтому необходимые таблицы создаются автоматически, а поддерживаемые изменения схемы применяются как миграции.

# важные особенности

## актуальный bot.py

при разработке всегда использовать **актуальный `bot.py` из github**.

не следует брать старые локальные копии как основу для новых изменений.

## sqlite

бот рассчитан на существующую sqlite-базу и содержит миграции для поддерживаемых изменений схемы.

файл:

```text
bot.db
```

не должен заменяться кодом из github.

## .env

`.env` содержит секреты и локальные настройки.

он не должен перезаписываться обычным обновлением кода.

## webhook и bot — разные процессы

telegram-бот и RollyPay webhook запускаются отдельно:

```text
vpn-bot.service
rollypay-webhook.service
```

перезапуск одного процесса не означает автоматический перезапуск другого.

## очередь рассылок

рассылки находятся в памяти процесса.

если бот перезапустить во время ожидания очереди, незавершённая очередь не восстанавливается из sqlite.

## блокировки пользователей

пользователи, которые заблокировали бота, сохраняются отдельно и исключаются из массовых рассылок.

## повторная обработка оплаты

оплаченный RollyPay payment не должен повторно продлевать подписку.

## совместимость со старыми клиентами

при поиске подписки бот сначала использует telegram id, а затем старый email. это позволяет работать со старыми записями 3x-ui.
